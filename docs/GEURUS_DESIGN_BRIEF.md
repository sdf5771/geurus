# Geurus — 디자인 발주서

> Claude Design에 그대로 붙여넣어 사용하는 문서.
> Claude Design은 프로젝트 지식과 연결되지 않으므로, **이 문서 하나로 맥락이 완결**되어야 한다.
> 결과물은 HTML로 export해 프로젝트 지식에 업로드한다.

---

## 0. 발주 배경 (Claude Design에 전달할 맥락)

**Geurus**는 Claude Code의 서브에이전트를 캐릭터로 시각화하는 **macOS 데스크톱 오버레이 앱**이다.
Claude Code가 작업을 위임하면 서브에이전트가 생기는데, 몇 개가 돌고 무엇을 하는지 알 방법이 없다.
Geurus는 서브에이전트 하나마다 **그루 한 마리**를 띄운다. — *"에이전트 하나, 그루 하나."*

그루는 기존 프로젝트 **GitGrove**의 마스코트다. 씨앗 몸통에 새싹이 돋은 정령이며,
머리 위 두 잎은 브랜치, 발밑 뿌리는 로컬 저장소를 뜻한다. 16×18 픽셀아트다.

Geurus는 GitGrove의 **디자인 시스템과 캐릭터를 공유**하되 별도 앱이다.
톤은 **아케이드 다크**. 배경은 짙은 네이비, 액센트는 골드 하나.

## 1. 반드시 지킬 규칙 ⚠️

### 1-1. 그루 사용 규칙 (GitGrove 브랜드 가이드)

| ✓ Do | ✗ Don't |
|---|---|
| **정수배(×N) 확대만** | 보간 확대 · 기울임 · **회전** |
| 다크 · 그리드 배경 위 | 흐리게(blur) · 그림자로 뭉개기 |
| 외곽선 없이 명암만으로 입체 | **몸통 골드 · 새싹 그린 임의 변경** |
| 16px 미만은 새싹·볼터치 생략 미니 버전 | 팔레트 밖 색 추가 |

### 1-6. 카피 톤

- 해요체, 한국어 먼저, 짧게. 주어(당신·제가) 생략
- 상태 조각은 **가운뎃점 `·`** 으로 연결 (쉼표·파이프 금지)
- 숫자는 서양 숫자, 99 초과는 `99+`
- 에러는 **사유 먼저, 코드는 뒤** — `인증이 필요해요 · 401`
- **상태는 그루가 표정으로 전하고, 글은 사실만 짧게 받친다**
- ✗ 느낌표 남발, "최고의"·"지금 바로", 장식용 이모지

```
✓ 충돌 발생 · 3 files
✗ 앗! 충돌이 발생했어요. 당황하지 마세요
```

## 2. 산출물

### 산출물 ① 포즈 그리드 3종 ⭐ 최우선

기존 `BASE`는 서 있는 자세 하나뿐이다. 움직임을 주려면 **몸통 그리드 자체가 다른 포즈**가 필요하다.

| 포즈 | 요구 사항 |
|---|---|
| `squash` | 몸통이 1px 눌리고 잎이 바깥으로 벌어짐. 착지·시작 |
| `stretch` | 몸통이 1px 늘어나고 잎이 안으로 모임. 도약 |
| `lean` | 몸통이 진행 방향으로 1px 기움. 이동 중 |

**제약**

- 캔버스는 **16 × 18 고정**. 벗어나지 말 것
- `BASE`와 **같은 문자 팔레트 키만** 사용
- 눈·입 영역(행 8~11)은 **패치로 덮이므로 BASE와 같은 좌표 유지**
- 스쿼시·스트레치는 CSS `scaleY`가 아니라 **그리드로 표현** (비정수 배율은 픽셀을 뭉갬)
- `lean`은 좌우 대칭 뒤집기로 반대 방향을 만들 수 있게 설계

**납품 형식**

```js
const POSE = {
  stand:   [...],  // 기존 BASE
  squash:  ["................", ...],
  stretch: ["................", ...],
  lean:    ["................", ...],
};
```

### 산출물 ② 모션 프레임 테이블 ⭐ 최우선

움직임은 **연속 좌표가 아니라 픽셀 격자 스냅** 방식이다. 프레임마다 위치·포즈·표정이 정해진 테이블로 표현한다.
부드러움은 **프레임 수와 유지 시간**으로 만든다. (정점에 오래 머물면 ease-in-out처럼 읽힘)

**필요한 모션 7종**

| 상태 | 의미 | 요구 |
|---|---|---|
| `idle` | 대기 | 기존 bob(위아래 흔들림) 계승. 루프 |
| `working` | 작업 중 | 빠른 bob + 잎 살랑. 루프 |
| `tool` | 툴 실행 중 | 좌우 완만한 이동. 루프 |
| `blocked` | 승인 대기 | 좌우 흔들림 + 땀 픽셀. 루프. **시선을 끌어야 함** |
| `done` | 완료·미확인 | 폴짝 + 반짝. 1회 재생 후 `idle` |
| `spawn` | 생성 | **×1 → ×2 → ×3 정수 배율로 자라남.** 1회 |
| `sleepy` | 장시간 유휴 | 아주 느린 bob + zzz. 루프 |

**납품 형식**

```js
const MOTION = {
  idle: {
    loop: true,
    frames: [
      { pose:'stand', dx:0, dy:0,  ms:180 },
      { pose:'stand', dx:0, dy:-1, ms:120 },
      { pose:'stand', dx:0, dy:-2, ms:100 },
      { pose:'stand', dx:0, dy:-3, ms:140 },
      { pose:'stand', dx:0, dy:-2, ms:100 },
      { pose:'stand', dx:0, dy:-1, ms:120 },
    ],
  },
  // ...
};
```

- `dx`/`dy`는 **스프라이트 픽셀 단위 정수**
- `scale` 필드는 `spawn`에서만 사용 (정수만)
- `expr` 필드로 프레임별 표정 지정 가능 (생략 시 상태 기본 표정)

### 산출물 ③ 말풍선

그루가 지금 무엇을 하는지 알리는 픽셀아트 말풍선.

**요구**

- 꼬리 방향 4종 (아래·위·좌·우) — 그루 위치에 따라 선택
- 픽셀아트 테두리. 라운드 코너는 픽셀 계단으로 표현
- 배경 `--c-bg-elevated`, 테두리 `--c-border-strong`
- 폭 가변. 최소 폭과 최대 폭 제시할 것 (넘치면 말줄임)
- **한글 + 숫자 혼용** — 한글 Noto Sans KR, 숫자·툴명 IBM Plex Mono
- 상태별 변형: 기본 / 경고(`--c-danger` 좌측 바) / 성공(`--c-success` 좌측 바)

**들어갈 카피 예시**

```
Bash 실행 중 · 40s
승인이 필요해요 · 3 files
완료 · 2m 15s
인증이 필요해요 · 401
```

---

### 산출물 ④ 정원 패널 레이아웃

그루들이 모여 있는 작은 패널. 창 테두리 없이 투명 배경 위에 뜬다.

**요구**

- 권장 크기 제시 (360×240 전후 가정, 조정 가능)
- 프로젝트가 여러 개일 때의 배치 규칙 — 프로젝트 = 화단/나무, 그 주위에 그루
- 그루가 많아질 때 처리 — 표시 상한과 `+N` 접기 표현
- 드래그 이동 영역 표시 (창 테두리가 없으므로 잡을 곳이 필요)
- 배경: 완전 투명 / 반투명 패널 두 안 제시

**표시 우선순위** — 여러 마리일 때 누구를 크게·앞에 둘지

```
승인 대기 > 비정상 종료 > 완료(미확인) > 작업 중 > 유휴
```

### 산출물 ⑤ 타입 구분 장치 ⚠️ 난제

서브에이전트는 타입이 있다 (`frontend`, `explore`, `backend` 등).
그런데 **몸통 골드·새싹 그린은 고정**이라 색으로 구분할 수 없다.

**색을 쓰지 않는 구분 방법 2~3안을 제시할 것.**

검토할 방향

- 잎 개수·모양 변형 (새싹은 그루의 정체성이므로 변주 여지 있음)
- 작은 배지를 발밑이나 옆에 배치
- `spawnDepth`(중첩 깊이)에 따른 정수 배율 차등 — ×3 / ×2 / ×1
- 말풍선에 타입명 표기로 대체

### 산출물 ⑥ 빈 상태 · 에러 상태

| 상황 | 그루 표정 | 카피 방향 |
|---|---|---|
| 에이전트 없음 | `sleepy` | "아직 일하는 그루가 없어요" 계열 |
| Claude Code 미실행 | `sleepy` | 다음 행동 제안 |
| 로그를 읽을 수 없음 | `conflict` | 사유 + 코드 |

GitGrove 빈 상태 선례: *"아직 커밋이 없어요 / 첫 커밋을 심으면 그루가 자라요"*

### 산출물 ⑦ 트레이 아이콘

독 아이콘을 숨기므로 **메뉴바 트레이가 유일한 조작 진입점**이다.

- macOS 메뉴바용 16×16 / 32×32 (Retina)
- 상태 반영 2~3종: 유휴 / 작업 중 / **승인 대기**(강조)
- 다크·라이트 메뉴바 양쪽에서 판독 가능해야 함
- 그루 전체를 넣기엔 작으므로 **새싹만 쓰는 축약형**도 검토

## 3. 납품 형식

**단일 HTML 파일 1개.** GitGrove 디자인 자산과 동일한 구조.

- 스프라이트는 이미지가 아니라 **문자 그리드 + 팔레트 + 렌더 함수**로
- `POSE`, `MOTION` 등 데이터는 **JS 상수로 그대로 노출** (복사해 앱에 이식할 수 있어야 함)
- 각 산출물을 섹션으로 나누고, 애니메이션은 **실제로 재생되게** 구현
- 섹션마다 라벨·설명 포함 (GitGrove 자산 문서와 같은 편집 방식)

> 이 HTML이 곧 스펙 문서이자 구현 소스가 된다. 데이터를 이미지로 굽지 말 것.

## 4. 우선순위

작업량이 많으면 아래 순서로 나눠 받는다.

1. **① 포즈 그리드 + ② 모션 테이블** — 없으면 구현이 시작 불가
2. **③ 말풍선 + ④ 정원 패널** — 화면 구성
3. **⑤ 타입 구분 + ⑥ 빈 상태 + ⑦ 트레이** — 마감

## 5. 붙여넣기용 요약 프롬프트

> Geurus라는 macOS 데스크톱 오버레이 앱의 디자인을 만들어줘.
> Claude Code의 서브에이전트를 캐릭터 「그루」로 시각화하는 앱이야.
> 그루는 내 기존 프로젝트 GitGrove의 마스코트로, 씨앗 몸통에 새싹이 돋은 16×18 픽셀 정령이야.
> 톤은 아케이드 다크 — 짙은 네이비 배경에 골드 액센트 하나.
>
> 아래 규칙과 자산을 그대로 지켜줘. (§1 전체 붙여넣기)
>
> 먼저 **포즈 그리드 3종(squash/stretch/lean)과 모션 프레임 테이블 7종**부터 만들어줘. (§2 ①②)
> 결과는 단일 HTML로, 스프라이트는 문자 그리드 + 팔레트 + 렌더 함수 방식으로,
> POSE·MOTION 데이터는 JS 상수로 노출하고, 애니메이션은 실제로 재생되게 해줘.
