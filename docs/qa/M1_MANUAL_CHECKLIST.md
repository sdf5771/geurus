# 마일스톤 1 — 수동 테스트 체크리스트

> 작성: qa 에이전트 (2026-09-15) · 대상: `feat/m1-overlay-shell`
> 자동 검증(앱 내부 캡처·IPC·창 속성)은 통과. 아래는 **사람의 눈과 손이 필요한 항목**만 모았다.
> 좌표는 측정 환경 기준(내장 Liquid Retina XDR, 논리 1512×982, scaleFactor 2). 다른 디스플레이면 창 위치가 달라진다.

## 공통 준비

- 빌드 실행: `npm run build && npm start` / dev 실행: `npm run dev` (DevTools가 필요하면 `GEURUS_DEVTOOLS=1 npm run dev` — 분리 창으로 자동으로 열림)
- 단일 인스턴스는 빌드(`npm start`)에만 걸린다. 이미 떠 있으면 두 번째 실행은 조용히 바로 종료. dev(`npm run dev`)는 잠금이 없어 빌드와 동시에 띄우면 그루·새싹이 2개가 된다. 빌드↔dev를 바꿀 때는 트레이 `종료`로 먼저 끈다
- 창 위치(좌상단 원점 pt): x 1136~1496, y 726~966 · 그루 히트박스: x 1304~1328, y 918~948
- ⌘⇧4 → 십자 커서 옆에 좌표 표시 (Esc 취소)
- 아래 앱: TextEdit에 긴 문서를 열어 화면 우하단까지 덮기
- 커서 모양이 히트 상태 표시 — TextEdit 위 I-beam, 그루가 클릭을 잡으면 화살표

## 1. 투명·잔상

- **준비**: 흰 배경(TextEdit)과 어두운 배경(바탕화면)을 번갈아 우하단에 둔다
- **조작**: 창 영역 360×240을 본다. TextEdit 창을 그 위로 천천히·빠르게 드래그한다
- **기대**: 그루 외 사각형·테두리·그림자·검은 판 없음. 드래그 후 흔적 없음
- **실패 시 기록**: ⌘⇧5 스크린샷, 배경 앱, 라이트/다크, 빌드/dev

## 2. 그루 밖 클릭 통과

- **준비**: TextEdit 활성, 문서가 창 영역 전체를 덮게
- **조작**: 창 안·그루 밖 여러 지점(좌상단, 그루 바로 좌·우·위, 그루와 창 바닥 사이)을 클릭하고 드래그로 텍스트 선택
- **기대**: 모든 지점에서 캐럿 이동·선택 가능, 커서 I-beam
- **실패 시 기록**: 통과 안 된 좌표, 전체가 막히는지 일부인지, 직전에 그루를 클릭했는지

## 3. 그루 위 클릭 잡힘

- **준비**: 2번과 동일. dev면 `GEURUS_DEVTOOLS=1 npm run dev`로 실행 → 분리된 DevTools 창 Console에서 레벨 **Verbose** 켜기 (앱 메뉴가 없어 ⌥⌘I로는 열리지 않음)
- **조작**: 그루 몸통·발·잎 클릭, bbox 안 투명 칸(좌상단 모서리 부근, 잎 바깥 빈칸)도 클릭
- **기대**: 커서 화살표, TextEdit 캐럿 불변. dev에서 `[geurus] geuru click captured x y`
- **실패 시 기록**: 통과해 버린 좌표, 커서 모양, 콘솔 출력 여부

## 4. 경계 깜빡임·빠른 이탈

- **조작 A**: 그루 좌·우·위 경계를 1px씩 천천히 넘나들며 커서 관찰
- **조작 B**: 그루 위에서 커서를 창 밖(위·왼쪽)으로 빠르게 뺀 직후, 창 안·그루 밖 클릭
- **기대**: 경계에서 커서가 한 번씩만 바뀜. B에서 클릭이 TextEdit으로 통과
- **실패 시 기록**: 깜빡인 경계, 막힌 영역과 복구 조건

## 5. 비활성 상태에서 히트 전환

- **준비**: 앱 실행 후 TextEdit을 클릭해 활성화. Geurus는 한 번도 클릭하지 않음
- **조작**: 커서를 그루 위로 천천히 올리고, 올린 채로 클릭
- **기대**: 커서 화살표로 전환, 클릭 잡힘(TextEdit 캐럿 불변)
- **실패 시 기록**: 커서 불변인지, 한 번 클릭 후에야 동작하는지, 체감 지연(초)

## 6. 그루 클릭 시 포커스 (결과만 기록)

- **준비**: TextEdit에서 타이핑 중
- **조작 A**: 타이핑을 멈추지 않은 채 다른 터미널에서 앱 실행 → 실행 직후 1~2초 입력 계속
- **조작 B**: 그루 한 번 클릭 → 곧바로 `abc` 입력 → ⌘R, ⌘W, ⌥⌘I를 차례로 누름
- **기대**: A에서 입력이 끊기거나 사라지지 않음(TextEdit 포커스 유지). B의 ⌘R·⌘W·⌥⌘I는 Geurus에 아무 일도 일으키지 않음(재로드·종료·DevTools 없음, 그루 유지)
- **기록**: A 입력 유실 여부 · B에서 `abc` 입력 대상(결과만 기록 — 포커스 정책 결정 근거) · 단축키 뒤 그루가 남아 있는지, 창 안 그루 밖 클릭이 통과하는지

## 7. 독 없음·트레이 종료

- **조작**: 독과 ⌘Tab에 아이콘 없는지 확인 → 메뉴바 새싹 → `종료` → 터미널에서 `pgrep -fl "node_modules/electron/dist"`
- **기대**: 독·⌘Tab에 없음, 메뉴 항목 `종료` 하나, 종료 후 오버레이·트레이 사라지고 `pgrep` 결과 없음. dev면 `npm run dev`도 종료
- **조작(추가)**: 앱이 떠 있는 상태에서 `npm start`를 한 번 더 실행 (빌드만 해당)
- **기대(추가)**: 두 번째 실행은 즉시 끝나고, 메뉴바 새싹 1개·그루 1마리 그대로
- **실패 시 기록**: 남은 프로세스, 종료까지 걸린 시간. 트레이가 안 보이면 메뉴바 아이템 수와 노치 가림 여부(측정 트레이 x=612)

## 8. 트레이 반전·선명도

- **조작**: 시스템 설정 > 화면 모드 라이트/다크 전환, 밝은·어두운 배경화면에서도 확인, 메뉴를 열어 강조 반전 확인
- **기대**: 새싹이 메뉴바 글자색에 맞춰 검정/흰색으로 바뀌고 선명한 2x 글리프
- **실패 시 기록**: 모드별 메뉴바 스크린샷, 흐림·색 고정 여부

## 9. 다른 Space·풀스크린

- **조작**: ⌃→/⌃←로 Space 전환, Mission Control(F3), Safari·TextEdit 풀스크린 Space에서 확인
- **기대**: 모든 Space·풀스크린 위에서 우하단 그루 표시, 전환 중 사라짐·깜빡임 없음. 풀스크린 위에서도 2·3번 동작
- **실패 시 기록**: 사라진 시점(전환 중/도착 후), 풀스크린 위 클릭 통과·잡힘 결과

## 10. 픽셀 선명도 (화면 기준)

- **조작**: 그루 부분 ⌘⇧4 캡처 → 미리보기 800% 이상 확대. 시스템 설정 > 디스플레이 해상도 설정 기록
- **기대**: 스프라이트 1픽셀 = 가장자리 또렷한 4×4 기기 픽셀, 번짐·1px 틈·겹침 없음
- **실패 시 기록**: 확대 캡처, 해상도 설정("기본" 외면 OS 스케일링으로 흐려질 수 있음), 외장 모니터 여부

## 11. dev·빌드 실조작 대조

- **조작**: 빌드와 dev에서 각각 2·3·7번 반복 (동시에 띄우지 말 것 — 빌드 잠금은 dev를 막지 못해 그루가 2마리 뜬다)
- **기대**: 동작 차이 없음(dev에서만 콘솔 로그)
- **조작(dev 추가)**: dev에서 `src` 파일을 저장
- **기대(dev 추가)**: 그루가 다시 그려지고, 저장 뒤에도 창 안 그루 밖 클릭이 통과한다
- **실패 시 기록**: 한쪽에서만 재현되는 항목과 모드

## 12. 렌더러 크래시 복구 (선택)

- **준비**: 빌드 실행, 우하단 그루가 보이는 상태. TextEdit을 창 영역 밑에 둔다
- **조작**: 터미널에서 `pkill -9 -f "geurus/node_modules/electron.*--type=renderer"` → 1초 기다리며 우하단 관찰 → 창 안 그루 밖·그루 위 클릭. 이것을 60초 안에 총 4번 반복
- **기대**: 1~3번째는 1초 안에 그루가 다시 나타나고 2·3번 동작 정상. 4번째 뒤에는 그루가 사라진 채 남고, 그 영역(360×240) 어디를 클릭해도 TextEdit으로 통과. 회색·흰색·검은 사각형 같은 흔적 없음. 트레이 `종료` 정상
- **실패 시 기록**: 몇 번째 크래시였는지, 남은 사각형 스크린샷, 막힌 클릭 영역
